# OpenCode V2

PurpleFlow запускает установленный `opencode` как отдельный CLI-агент. Его можно выбрать для любой роли, служебного сканирования, менеджера и обычного чата.

## Настройка

1. Установите **OpenCode V2** по [официальной инструкции](https://opencode.ai/v2/docs/cli). В Windows используйте standalone-сборку. Кнопка установки инструментов PurpleFlow показывает инструкцию; автоматическая установка OpenCode не выполняется.
2. Настройте провайдер и авторизацию в OpenCode и проверьте обычный запрос из терминала.
3. В PurpleFlow откройте **Настройки → Инструменты**, нажмите «Найти снова». При необходимости укажите путь к `opencode` или `opencode.exe` вручную.
4. В **Моделях** выберите `opencode` для нужных ролей. Имя модели — `provider/model`, вариант — `provider/model#variant`. Пустое поле использует модель по умолчанию OpenCode. Быстрая настройка назначает OpenCode всем ролям с пустыми моделями; уровни стоимости для произвольных провайдеров не подставляются.
5. «Проверить подключение» отправляет короткий запрос установленным агентам и расходует их токены.

OpenCode всегда использует собственную конфигурацию, провайдеры, плагины и авторизацию. Общий AI-прокси PurpleFlow и переключатель «Мои настройки Claude и Codex» к нему не применяются. Файлы конфигурации OpenCode интеграция не меняет.

Список моделей загружается командой `opencode --standalone models`, без запроса к модели. В настройках используется пользовательская конфигурация, в чате — конфигурация выбранного проекта. Каталог кэшируется на минуту и проверяется при открытии экрана и возвращении фокуса в приложение. При ошибке видна подсказка; ручной ввод `provider/model#variant` остаётся доступен.

## Контракт адаптера

- Команда: `opencode --standalone run --format json --thinking --auto`. Промпт передаётся через stdin, изображения — повторяемым `--file`. Модель и сессия — отдельными аргументами.
- Частный сервер принадлежит процессу CLI. Отмена и таймауты используют существующий механизм остановки дерева процессов PurpleFlow, не останавливая общий сервер пользовательского OpenCode.
- JSONL-события `text`, `reasoning`, `tool_use`, `step_finish`, `retry`, `error` преобразуются в общие шаги и расход. Ошибка после частичного ответа остаётся ошибкой. Неизвестные события допускаются; завершение без `step_finish` считается несовместимым или оборванным потоком.
- Расход берётся из `step_finish`: input, visible output + reasoning, cache read/write, cost. Повторный шаг не учитывается дважды.
- Чат сохраняет `sessionID` и передаёт его через `--session` на следующем ходе. Изменение режима прав сбрасывает сессию; при новом запуске передаётся предыдущая переписка.
- В режиме чтения через `OPENCODE_CONFIG_CONTENT` добавляется отдельный агент `purpleflow-readonly`: deny-all, затем разрешения чтения, поиска, веб-поиска и навыков. Shell, запись, подагенты, execute и MCP недоступны. Это ограничение инструментов OpenCode, **не песочница ОС**; пользовательские плагины остаются доверенным кодом.
- Реализация и визуальная проверка используют обычные разрешения OpenCode с `--auto`. Для визуальной проверки нужен shell браузерного инструмента; запрет менять код задаётся инструкцией стадии.
- Схема структурированного ответа передаётся в инструкции: у V2 `run` нет флага output-schema. Полученный JSON разбирают существующие стадии PurpleFlow.

## Проверка и источники

Локальные тесты не обращаются к моделям:

```sh
npx tsx --test core/src/opencode.test.ts
npm run check
npm run build
```

Проверка установленного CLI без запроса к провайдеру:

```sh
npm run check:agents -w core -- --only=opencode
```

Ручная проверка реального JSONL-контракта (расходует токены):

```sh
npm run check:agents -w core -- --only=opencode --live
```

Контракт изучен по CLI V2.2.5 и исходникам OpenCode (`packages/cli/src/run/run.ts`, `noninteractive.ts`, `packages/core/src/session/usage.ts`). При обновлении CLI стоит повторять live-проверку.

Референс интеграции — [stablyai/orca](https://github.com/stablyai/orca): диалект ACP OpenCode (`src/main/acp/acp-dialects/opencode-dialect.ts`) и распознавание headless-команд. Оттуда учтены вложенные метаданные результата инструмента, коды выхода и граница жизни `run`. PurpleFlow сохраняет свою CLI-архитектуру; ACP-транспорт Orca не требуется.
