Определи, какими командами в этом проекте ставят зависимости, запускают линтер и тесты. Работай только на чтение: смотри файлы сборки (package.json, lock-файлы, Makefile, pyproject.toml, go.mod, Cargo.toml, конфиги линтеров, CI в .github/workflows, README).

Правила:
- Команды запускаются из корня репозитория в чистой копии без node_modules и прочих зависимостей. Поэтому `setup` — то, что нужно выполнить один раз перед работой (например `npm ci`, `pnpm install --frozen-lockfile`, `uv sync`). Если зависимостей нет — пустая строка.
- `lint` — линтер и/или проверка типов, которые есть в проекте (например `npm run lint`, `npx tsc --noEmit`, `ruff check .`). Не выдумывай: если линтера нет — пустая строка.
- `test` — команда, которая запускает все тесты и завершается сама (без watch-режима, без интерактива).
- Предпочитай скрипты проекта и те же команды, что в CI.
- `run` — команда, которая запускает приложение для просмотра в браузере (dev-сервер), если это веб-приложение. Подставь `{port}` вместо порта так, чтобы команда его учитывала: например `npm run dev -- --port {port}` (Vite), `npx next dev -p {port}`, `PORT={port} npm start`. `url` — адрес главной страницы с тем же `{port}`, например `http://localhost:{port}`. Если интерфейса нет (библиотека, CLI, бэкенд без UI) — обе пустые строки. Если фронтенду для работы нужен свой бэкенд или API из этого же репозитория (монорепо: `apps/web` ходит в `apps/api`), `run` должен поднимать **оба** в одной команде, фоном через `&`, например `(cd apps/api && npm run dev) & (cd apps/web && npx next dev -p {port})`; порт API бери из его конфига или .env.example.
- `visual` — короткая инструкция для агента, который будет проверять приложение в браузере: как получить тестовый вход (сид, тестовый пользователь из README, .env.example, фикстур), какие сервисы должны работать (база, очереди), куда идти после входа. Только то, что нашёл в файлах; паролей не выдумывай. Если нечего сказать — пустая строка.
- Для каждой команды в `notes` одной короткой фразой по-русски скажи, откуда она взята.

Ответь только JSON без пояснений:
{"setup": "...", "lint": "...", "test": "...", "run": "...", "url": "...", "visual": "...", "notes": {"setup": "...", "lint": "...", "test": "...", "run": "..."}}
